# TraeCode 对拍练习记录（空安全、命名参数与整除）

对拍题目来源：TraeCode 生成，范围指定为空安全、命名参数、整除。

对拍流程：先手写答案，再由 TraeCode 生成参考答案与讲解，逐题核对，分歧部分讲解并记录。

## 题目与对拍明细

### 第1题：?. 与 ?? 组合
- 我的答案：0 和 2
- AI 参考答案：0 和 2
- 对拍结果：一致。
- 复核说明：nickname 为 null 时 ?. 短路返回 null，由 ?? 兜底输出 0；赋值 'hu' 后长度为 2。

### 第2题：??= 是否覆盖 与 汉字 length
- 我的答案：手写"第二次"和 3（打字版为"第一次"和 1）
- AI 参考答案："第一次" 和 3
- 对拍结果：不一致
- 分歧复核：
  - 值写错：??= 只在变量为 null 时才赋值。a 第一次被赋成"第一次"后已非 null，第二个 ??= 不覆盖，所以输出"第一次"。
  - 最终结论：??= 非 null 不覆盖；"第一次".length == 3。已记入错题本。
### 第3题：命名参数默认值
- 我的答案：李华 18 2班，小明 20 未分班
- AI 参考答案：李华 18 2班，小明 20 未分班
- 对拍结果：一致。
- 复核说明：传了 className 就用传入值"2班"，不会再走 ?? '未分班'；age 未传用默认值 18；小明没传 className，由 ?? 兜底显示"未分班"。

### 第4题：/、~/、% 与混合运算
- 我的答案：3.5、3、1、63.3循环
- AI 参考答案：3.5、3、1、66.33333333333333
- 对拍结果：一致
- 复核说明：~/ 取整商，/ 结果为 double，int + double 结果为 double。混合运算先分开算再相加，避免口算失误。

### 第5题：! 的编译期与运行期
- 我的答案：最初写编译报错，最终结论改为编译通过，运行报错
- AI 参考答案：编译通过，运行时抛错（Null check operator used on a null value）
- 对拍结果：不一致
- 分歧复核结果：
  - "编译报错"的表述不对：! 语法本身合法，编译器不做 null 静态分析，因此编译能通过。
  - 真正的错误发生在运行时：s 实际为 null，执行到 s! 时抛出 Null check operator used on a null value。
  - 对比实验：若写 show(score: s)（不加 !），才是编译错误——int? 不能直接传给 int。
  - 最终结论：! 是运行时断言，把报错从编译期推到运行期。这一分歧已记入错题本。

## 对拍小结
5 题中 3题一致，2题分歧。分歧集中在两处：??= 的覆盖规则和! 的报错时机，均已复核并记录。
